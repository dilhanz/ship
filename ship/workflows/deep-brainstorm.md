# Workflow: deep-brainstorm

This workflow runs parallel research agents before handing off to the brainstormer. It is invoked by `/ship:feature-brainstorm --deep`.

---

## Purpose

Perform comprehensive market, competitive, and technical research on a feature idea, synthesize the findings into a research brief, and then start a brainstorming session with that context.

## Prerequisites

- A working directory (the project root) must be set
- The user provides a feature idea along with `--deep`

## Steps

### Step 1 — Extract the feature idea

Parse `$ARGUMENTS` to separate the `--deep` flag from the feature idea text. The idea is everything remaining after removing `--deep`.

If no idea text remains after removing `--deep`, ask the user:

> "What feature would you like to explore? Describe the idea in a sentence or two."

Wait for their response before continuing.

### Step 2 — Ensure `.planning/` exists

Run `mkdir -p .planning` to ensure the planning directory exists.

### Step 3 — Read project context

Read the following files to understand the project. Skip any that don't exist — do not ask the user about missing files.

1. `.planning/PROJECT.md` — vision, stack, constraints
2. `.planning/REQUIREMENTS.md` — existing features
3. `.planning/STATE.md` — current phase and status
4. `.planning/ROADMAP.md` — planned and completed phases

Summarize the project context briefly for yourself (do not output it to the user). You will include this context in each research agent prompt.

### Step 4 — Launch parallel research agents

Spawn **all three** research agents in a **single message** using the Task tool. Each agent should receive the feature idea and a brief summary of the project context.

#### Agent 1: Market & User Research

Prompt the agent to research:
- Similar features in existing products and how users interact with them
- User expectations and common UX patterns for this type of feature
- Market trends related to this feature area
- Pain points and current workarounds users employ without this feature

The agent should perform 3-5 WebSearch queries and use WebFetch to read the most relevant results. It should return structured findings with source URLs.

#### Agent 2: Competitive Analysis

Prompt the agent to research:
- How competitors or similar products implement this type of feature
- Common implementation patterns — what works and what fails
- User feedback on competitor implementations (reviews, forums, social media)
- Differentiation opportunities — gaps in existing solutions

The agent should perform 3-5 WebSearch queries and use WebFetch to read the most relevant results. It should return structured findings with source URLs.

#### Agent 3: Technical Feasibility

Prompt the agent to research:
- Implementation patterns and architectural approaches for this type of feature
- Relevant libraries, APIs, or services that could be used
- Technical trade-offs between different approaches
- Common pitfalls and failure modes to watch for

The agent should perform 3-5 WebSearch queries and use WebFetch to read the most relevant results. It should return structured findings with source URLs.

**Important:** All three agents must be launched in a single message (parallel execution). Use `subagent_type: "general-purpose"` and `model: "sonnet"` for each.

### Step 5 — Synthesize into DEEP-RESEARCH.md

Once all three agents return, synthesize their findings into `.planning/DEEP-RESEARCH.md`:

```markdown
# Deep Research: [Feature idea — concise name]

_Generated by /ship:feature-brainstorm --deep on [date]_

## Feature Idea

[1-2 sentence description of the feature being researched]

## Market & User Research

[Synthesized findings from Agent 1. 4-8 bullet points covering user expectations, UX patterns, market trends, and pain points. Include specifics — product names, patterns observed.]

## Competitive Analysis

[Synthesized findings from Agent 2. 4-8 bullet points covering competitor implementations, what works/fails, user sentiment, and differentiation opportunities.]

## Technical Feasibility

[Synthesized findings from Agent 3. 4-8 bullet points covering implementation approaches, relevant tech, trade-offs, and pitfalls.]

## Key Takeaways

[3-5 bullets. The most important insights that should shape the brainstorming conversation. Focus on what's actionable.]

## Sources

[Bulleted list of URLs referenced across all three research areas]
```

**Error handling:** If one or two agents fail or return empty results, note the gap in the relevant section (e.g., "Research unavailable — consider investigating manually") and proceed. If all three agents fail, skip writing DEEP-RESEARCH.md and proceed directly to the brainstormer, noting that research could not be completed.

### Step 6 — Hand off to the brainstormer

Tell the user:

> "Research complete — findings saved to `.planning/DEEP-RESEARCH.md`. Starting brainstorming session with this context."

Then follow the agent instructions at `.claude/agents/ship-feature-brainstormer.md`, passing the feature idea as context. The brainstormer will detect and incorporate the research file automatically.
